# FACEIT Draft — балансировщик турнира

Локальная веб-программа на Python без внешних зависимостей. Интерфейс открывается в браузере, а API-ключ отправляется только локальному серверу и не сохраняется на диск.

## Запуск

1. Установите Python 3.10 или новее.
2. В этой папке выполните `python server.py`.
3. Откройте `http://127.0.0.1:8765`.
4. Введите никнеймы FACEIT, вставьте API key и нажмите **Загрузить FACEIT**. Либо импортируйте CSV.
5. Нажмите **Распределить команды**. Результаты можно скачать CSV.

API key FACEIT создаётся в [FACEIT Developer Portal](https://developers.faceit.com/). Ключ нужен для Data API v4.

## Публичная страница проекта

Короткая страница для проекта находится в [`docs/index.html`](docs/index.html). Чтобы получить адрес GitHub Pages:

1. Опубликуйте эту папку в своём GitHub-репозитории.
2. В репозитории откройте **Settings → Pages**.
3. В **Build and deployment** выберите **Deploy from a branch**, затем нужную ветку и папку **/docs**, сохраните.
4. После публикации GitHub покажет адрес вида `https://<ваш-логин>.github.io/<имя-репозитория>/`. Его можно указать в поле Company website.

В текущей локальной папке GitHub remote ещё не настроен, поэтому опубликованного адреса пока нет.

## Импорт истории из CSV

Пример — [players-template.csv](players-template.csv). Поддерживаемые заголовки: `nickname`, `level`, `elo`, `faceit_rating`, `matches`, `win_rate`, `kills_avg`, `deaths_avg`, `assists_avg`, `adr_avg`, `kast_avg`, `impact_avg`, `sniper_rate`, `sniper_kills`, `entry_rate`, `entry_count`, `entry_success`, `trade_share`, `trade_kills`, `utility_damage`, `flashes_per_round`, `enemies_flashed`, `survival`, `dpr`, `clutch_1v1`, `clutch_1v2`, `role`. Нужен столбец nickname; остальные поля могут быть пустыми. В рейтинге указывайте средний FACEIT Rating по матчам, а в matches — число матчей, откуда он рассчитан. Для полной истории добавьте один сводный ряд на игрока: рейтинг и объём выборки должны быть посчитаны по его матчам.

Для проверки балансировщика есть [players-80-level10.csv](players-80-level10.csv) с 80 публичными профилями из европейской таблицы лидеров. Там только уровень и Elo, без FACEIT Rating; список взят с [FPLLeaderboards](https://fplleaderboards.com/top-100), стороннего сайта, поэтому ники и ранги могут измениться. CSV и загрузка профилей через API поддерживают до 80 игроков за один запрос; при загрузке такого количества FACEIT может ограничить частоту запросов.

Приоритет API: нажмите **Импорт CSV** после загрузки профилей, если CSV должен заменить текущий набор данных.

## Модель распределения

- Расчётная сила сочетает level/Elo (45%), performance (50%) и объём истории (5%). Если FACEIT Rating доступен, performance смешивает его с матчевой статистикой; иначе использует статистику. K/D/A, ADR, KAST и Impact нормализуются по шкалам и для малой выборки притягиваются к нейтральному значению.
- HLTV-style estimate — прозрачная приближённая оценка по доступным средним показателям, а не официальный или точно воспроизведённый HLTV Rating 2.0: HLTV не раскрывает формулу. KAST/Impact учитываются только при наличии в данных.
- Игрокам можно вручную назначить `entry`, `second`, `awper`, `support`, `igl`, `lurker` или `flex`. Роли можно предложить по статистике кнопкой «Предложить роли по статистике» или передать в CSV в столбце `role`. Поддерживаются Entry, Second Fragger, AWPer, Support/Anchor, IGL, Lurker и Flex; основные роли балансируются по количеству, Flex и пустая роль не ограничиваются. IGL и Flex не выводятся из этих индивидуальных статов автоматически. Автоподбор использует entry, sniper/AWP, trade, utility, flash, survival и clutch метрики, только когда FACEIT API их вернул. Это эвристика, а не достоверная разметка роли.
- После начального распределения алгоритм улучшает одновременно разницу средней силы и дисбаланс по ролям обменами игроков между командами.
- Капитан выбирается по статистической эвристике (активность, win rate, Rating и матчевые показатели) с небольшим бонусом для назначенной роли IGL. Коммуникацию и лидерские качества эти данные не измеряют.
- Официальная пагинация API ограничивает матчевые stats диапазоном offset до 200. API-режим может охватить лишь часть истории. Для большего покрытия импортируйте сводную CSV статистику. Отсутствующие KAST/Impact не подменяются.

## Технологии

Python standard library (`http.server`, `urllib`) + встроенный HTML/CSS/JavaScript. Внешние пакеты не требуются.
